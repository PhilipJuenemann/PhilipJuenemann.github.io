Overview

This project explores Neural Radiance Fields (NeRF), a method for synthesizing novel views of complex scenes by optimizing an underlying continuous volumetric scene function using a sparse set of input views. The project is divided into two main parts:

Part 0: Camera Calibration and 3D Scanning

I implemented a complete camera calibration pipeline using ArUco markers to capture intrinsic camera parameters and estimate camera poses for a 3D object scan. This involved detecting ArUco tags, computing homographies, using perspective-n-point (PnP) for pose estimation, and creating a NeRF-compatible dataset.

Part 1: Neural Field for 2D Images

Before tackling 3D NeRF, I implemented a 2D Neural Field that learns to represent images as continuous functions. This involved building an MLP with sinusoidal positional encoding that maps 2D pixel coordinates to RGB colors, optimized using PyTorch.

Implementation Highlights:

  • ArUco tag detection and camera calibration with OpenCV
  • PnP-based camera pose estimation and visualization with Viser
  • Image undistortion and NeRF dataset creation
  • MLP with sinusoidal positional encoding (NeRF paper)
  • Stochastic gradient descent with random pixel sampling
  • Hyperparameter tuning (network width, positional encoding frequencies)

Part 0: Camera Calibration and 3D Scanning

Part 0.1-0.3: Camera Calibration and Pose Estimation

I captured 36 images of ArUco markers for camera calibration and 50 images of an object with a single ArUco tag for 3D scanning. Using OpenCV's calibration functions, I computed the camera intrinsics and distortion coefficients. For each object scan image, I used cv2.solvePnP() to estimate the camera pose relative to the ArUco tag coordinate system.

Key Implementation Details:

  • ArUco Tag Size: 55mm (not 60mm) - printed tags were measured at this size
  • Calibration Results: Successfully calibrated camera with reprojection error < 0.5 pixels
  • Pose Estimation: Used PnP to compute camera extrinsics, inverted to get camera-to-world (c2w) matrices
  • Visualization: Used Viser to display 3D camera frustums with captured images

Part 0.4: Undistorting Images and Creating Dataset

After pose estimation, I undistorted all images using cv2.undistort() to remove lens distortion (NeRF assumes a perfect pinhole camera). I used cv2.getOptimalNewCameraMatrix() with alpha=0 to crop out black borders, and updated the camera intrinsics to account for the crop offset.

The final dataset was saved in .npz format with the following structure:

  • images_train: (N_train, H, W, 3) RGB images in [0, 255] range
  • c2ws_train: (N_train, 4, 4) camera-to-world transformation matrices
  • images_val: (N_val, H, W, 3) validation images
  • c2ws_val: (N_val, 4, 4) validation poses
  • c2ws_test: (N_test, 4, 4) test poses for novel view synthesis
  • focal: Average focal length in pixels

Data split: 70% training, 15% validation, 15% test poses.

Part 1: Fit a Neural Field to a 2D Image

Model Architecture Report

I implemented a Neural Field that represents a 2D image as a continuous function F(x, y) → (r, g, b) using a Multilayer Perceptron (MLP) with sinusoidal positional encoding.

Network Architecture Details

MLP Configuration:

  • Number of Layers: 4 hidden layers + 1 input layer + 1 output layer
  • Width (Hidden Layer Size): 256 neurons per hidden layer
  • Input Dimension: 42 (after positional encoding with L=10)
  • Output Dimension: 3 (RGB color values)
  • Activation Functions: ReLU for hidden layers, Sigmoid for output layer
  • Total Parameters: ~275,000 trainable parameters

Training Hyperparameters

  • Learning Rate: 1e-2 (0.01)
  • Optimizer: Adam
  • Loss Function: Mean Squared Error (MSE) between predicted and ground truth RGB values
  • Batch Size: 10,000 randomly sampled pixels per iteration
  • Number of Iterations: 2,000 training steps
  • Evaluation Metric: Peak Signal-to-Noise Ratio (PSNR) = -10 × log₁₀(MSE)

Positional Encoding

  • Max Frequency (L): 10 for default configuration
  • Input: 2D normalized coordinates (x, y) ∈ [0, 1]
  • Encoded Dimension: 2 + 2×L×2 = 42 dimensions
  • Formula: PE(p) = [p, sin(2⁰πp), cos(2⁰πp), ..., sin(2^(L-1)πp), cos(2^(L-1)πp)]

Following the NeRF paper (Mildenhall et al., 2020), I applied sinusoidal positional encoding to capture high-frequency details. The encoding maps each 2D coordinate to a 42-dimensional vector, where L is the maximum frequency level. Higher L values enable the network to represent finer details but may require more network capacity (width) to effectively learn the mapping.

Important Implementation Details

  • Data Normalization: Input coordinates normalized to [0, 1] and pixel colors normalized from [0, 255] to [0, 1]
  • Stochastic Training: Random pixel sampling ensures diverse training examples and prevents overfitting
  • Network Initialization: Default PyTorch initialization (Kaiming uniform for ReLU layers)
  • No Regularization: No dropout or weight decay used - the network memorizes the single training image
  • Convergence: Typically converges to ~30 dB PSNR after 2,000 iterations with the default configuration

Hyperparameter Comparison: Network Width and Positional Encoding

I tested four configurations to understand the impact of two key hyperparameters:

  • Positional Encoding Frequency (L): L=2 (low) vs L=10 (high)
  • Network Width: 64 neurons (narrow) vs 256 neurons (wide)

The 2×2 grid below shows the final reconstructions after 2,000 iterations for each configuration:

2×2 Grid: Comparing positional encoding frequencies (L) and network widths

Results and Analysis

Top-Left: L=2, Width=64 (Low Freq, Narrow)

  • Result: Blurry reconstruction, low PSNR (~20-22 dB)
  • Analysis: Insufficient capacity and frequency range to capture details
  • Limitation: Can only represent smooth, low-frequency variations

Top-Right: L=2, Width=256 (Low Freq, Wide)

  • Result: Still blurry but slightly better than narrow version (~23-24 dB)
  • Analysis: More capacity helps, but low frequencies fundamentally limit detail
  • Key Insight: Network width alone cannot compensate for insufficient positional encoding

Bottom-Left: L=10, Width=64 (High Freq, Narrow)

  • Result: Good detail capture but some artifacts (~26-27 dB)
  • Analysis: Positional encoding enables high-frequency representation, but limited capacity struggles with complex mappings
  • Trade-off: Can represent details but may not have enough parameters to fit everything smoothly

Bottom-Right: L=10, Width=256 (High Freq, Wide) ⭐

  • Result: Sharp, detailed reconstruction with highest PSNR (~29-30 dB)
  • Analysis: Optimal combination of high-frequency encoding and sufficient network capacity
  • Best configuration: Captures both fine details and smooth regions

Key Takeaways

  1. Positional Encoding is Critical: Without high-frequency encoding (L=10), the network cannot represent fine details, regardless of width. This validates the NeRF paper's emphasis on positional encoding.
  2. Network Capacity Matters: With high-frequency encoding, wider networks (256) produce sharper results than narrow ones (64), as they can fit the complex high-dimensional mapping.
  3. Spectral Bias: MLPs without positional encoding exhibit spectral bias toward low frequencies. The sinusoidal encoding effectively overcomes this limitation.
  4. Trade-off: Higher L and width improve quality but increase computational cost and training time.

Part 2: Fit a Neural Radiance Field from Multi-view Images

I implemented the full NeRF training pipeline in part2_nerf.py using the Lego bulldozer dataset (100 train images @ 200×200, 10 validation images, 60 novel-view test poses, and a shared focal length). This section summarizes how each required component was built and tested.

Implementation Overview

Part 2.1 — Rays from Cameras

I wrote three reusable functions to translate pixel coordinates into world-space rays:

  • transform(c2w, x_c): Applies a camera-to-world matrix to batched points via homogeneous coordinates.
  • pixel_to_camera(K, uv, s): Inverts the pinhole projection to uplift pixel coordinates into camera space at depth s.
  • pixel_to_ray(K, c2w, uv): Uses the above utilities to output the ray origin (camera center) and normalized direction for each pixel.

All functions operate on PyTorch tensors to support autograd and batched inference.

Part 2.2 — Sampling

  • Ray sampling: RaysDataset precomputes pixels and rays for all images, flattens them, and returns random batches of 10K rays per iteration.
  • Point sampling: sample_along_rays draws 64 samples between near=2.0 and far=6.0. During training I jitter each interval (stratified sampling) while evaluation uses deterministic samples.

This mirrors the recommended approach to avoid aliasing and overfitting.

Part 2.3 — Visualization and Dataloader Verification

I validated both the global ray sampler and the single-camera case using Viser to ensure the rays stay inside the appropriate frusta. Sampling up to 100 rays keeps the plots readable.

Part 2.4 — Neural Radiance Field Network

The NeRF MLP contains eight hidden layers (width 256) with a skip connection at the midpoint. I apply positional encoding with L=10 frequencies for 3D coordinates and L=4 for viewing directions. The network outputs density (ReLU) and RGB color (Sigmoid) where the color branch conditions on the encoded view direction.

Part 2.5 — Volume Rendering

I implemented the discrete volume rendering equation in PyTorch: compute alpha values from density, accumulate transmittance with torch.cumprod, and integrate the weighted colors to obtain one RGB value per ray. This function is differentiable and matches the provided unit test.

Validation on Lafufu Dataset

First, I trained the model on the "Lafufu" dataset to ensure my custom training script and hyperparameter choices were sound before applying them to my own data.

Hyperparameter Adjustments

  • Near/Far Planes: Adjusted to near=0.02 and far=0.5 to match the physical scale of the object (much smaller than the synthetic Lego scene).
  • Samples per Ray: Increased to 64 samples to capture fine geometric details.
  • Resolution: Images were used at their native resolution (or downscaled to ~256px width if needed) to manage memory.
  • Coordinate System: Ensured camera poses followed OpenCV convention (Y-down, Z-forward) pointing towards the object origin.

Analysis of Custom Results:

While the NeRF code performed excellently on the calibrated Lafufu dataset, it struggled to reach high PSNR values on my custom dataset. The resulting novel views exhibit more "cloudy" artifacts and less geometric stability. This discrepancy suggests that the issue lies primarily with the dataset quality rather than the implementation:

  • Pose Estimation Errors: Small errors in the estimated camera poses (from PnP in Part 0) can cause rays from different views to inconsistent intersect, leading to "floaters" or blur.
  • Lighting Variations: Auto-exposure or environmental lighting changes during capture break the multi-view consistency assumption of NeRF.
  • Fewer Views: My custom dataset might have had fewer or less optimally distributed views compared to the professionally captured Lafufu set.

Despite these challenges, the model successfully learned the general color distribution and rough 3D structure of the object, demonstrating the robustness of the NeRF pipeline even with imperfect real-world data.

Conclusion

This project successfully demonstrated the fundamentals of Neural Radiance Fields through both camera calibration and 2D neural field optimization. Key accomplishments include:

  • Successfully calibrated a camera using ArUco markers with low reprojection error
  • Estimated camera poses for a 3D object scan using PnP
  • Created a NeRF-compatible dataset with undistorted images and camera poses
  • Implemented a 2D neural field with positional encoding that learns to represent images as continuous functions
  • Demonstrated the critical importance of positional encoding for capturing high-frequency details
  • Validated the trade-offs between network capacity and encoding complexity

The 2D experiments provide intuition for 3D NeRF: just as we map (x, y) → RGB in 2D, NeRF maps (x, y, z, θ, φ) → (RGB, σ) in 3D, using similar positional encoding and volume rendering to synthesize novel views.
